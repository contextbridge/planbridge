# Generated AI-tool config

The root `AGENTS.md` and `CLAUDE.md`, `.claude/rules/`, `.agents/memories/`, `.mcp.json`,
and the `[mcp_servers.*]` tables in `.codex/config.toml` are **generated by
[rulesync](https://github.com/dyoshikawa/rulesync)** from `.rulesync/`. Do not edit them
directly: the next `just generated rulesync` overwrites the change, and CI
(`just generated rulesync-check`) fails on the drift.

To change any of them:

1. Edit the source under `.rulesync/` — `.rulesync/rules/*.md` or `.rulesync/mcp.json`.
2. Run `just generated rulesync` to regenerate.
3. Commit the source and the regenerated output together.

`.rulesync/rules/overview.md` is the `root: true` rule and produces both root files. Every
other rule is path-scoped through its `globs` and produces one file per tool.

`.codex/config.toml` is only partly generated — its `approval_policy`, `sandbox_mode`, and
`[sandbox_workspace_write]` blocks are hand-maintained and rulesync leaves them alone.

Two things in this repo are **not** rulesync's: the per-package `AGENTS.md` / `CLAUDE.md`
files under `packages/`, which stay hand-written, and `packages/skills/sources/**/SKILL.md`,
which the CLI's own codegen renders into `harnessIntegrations/` (see the
**planbridge-skills** rule).
